# Direct Campaign Manager

Веб-приложение для массового запуска рекламных проектов Яндекс Директа через Click.ru API, на аккаунтах из общего пула ParsYa (`yandex_accounts` в MySQL). На каждый запуск приложение само провизионирует новый Яндекс-аккаунт из пула, создаёт для него отдельный счётчик Яндекс Метрики и цель `lead`, и создаёт полный черновик кампании (объявление, ключевые фразы, сайтлинки, колл-ауты). Запуск показов (активация кампании) не выполняется автоматически.

## Режим кампаний

В настройках проекта доступны два варианта:

- **Отдельные кампании** — одна кампания для Поиска и одна для РСЯ.
- **Одна ЕПК** — одна Единая перфоманс-кампания с включёнными местами показа Поиск и Рекламная сеть Яндекса.

Настройка сохраняется для каждого проекта. Это именно выбор шаблона создания, а не переключатель мест показа для уже существующих кампаний.

## Стек

- Python 3.12
- FastAPI + Uvicorn
- SQLite для начального развёртывания
- HTTPX для Click.ru API
- Защита интерфейса через HTTP Basic Auth

## Запуск локально или на сервере

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Заполните .env уникальным паролем, CLICKRU_API_TOKEN и PARSYA_POOL_API_TOKEN
uvicorn --env-file .env app.main:app --host "${APP_HOST:-127.0.0.1}" --port "${APP_PORT:-8000}"
```

Откройте `http://127.0.0.1:8000`. Не публикуйте приложение в интернет без HTTPS и уникального пароля администратора. Для внешнего доступа используйте reverse proxy с TLS.

В Docker:

```bash
docker compose up --build -d
```

## Публикация через Nginx и HTTPS

Конфигурация поддомена `реклама.союзюристовроссии.рф` и пошаговые команды: [`deploy/README.md`](deploy/README.md). Сам сервер нужно настроить по SSH: репозиторий не имеет удалённого shell-доступа. Сначала запустите приложение на `127.0.0.1:8000`, затем включите Nginx reverse proxy и выпустите сертификат Certbot.

## Click.ru API

Базовый URL: `https://api.click.ru`. Документация и Swagger: https://api.click.ru/V0/docs/

Приложение использует:
- `GET /V0/user` — проверка токена;
- `GET /V0/integrations` — список подключённых интеграций;
- `GET /V0/accounts` — список рекламных аккаунтов;
- API-прокси Яндекс Директа (`Campaigns.add`, `AdGroups.add`, `Keywords.add`, `Ads.add`, `Sitelinks`, `AdExtensions`) — создание черновика кампании под аккаунтом из пула;
- `GET /V0/stat` — запрос статистики Click.ru (после выбора периода и аккаунтов).

Лимиты API и права доступа определяются Click.ru. Приложение не создаёт почтовые аккаунты Яндекса и не обходит этап подключения/авторизации Яндекс ID в Click.ru.

## Аккаунты и Метрика — только через пул ParsYa

Приложение само не создаёт рекламные аккаунты Директа и не подключает Яндекс ID вручную — это раньше делалось отдельной кнопкой/OAuth-подключением, сейчас убрано как избыточное. Вместо этого каждый массовый запуск (`POST /api/projects/{id}/campaigns/bulk-create`) провизионирует НОВЫЙ Яндекс-аккаунт из общего пула ParsYa (`yandex_accounts` в MySQL), читает его Metrika OAuth-токен оттуда же через read-only API `parsya-control` (`PARSYA_POOL_API_URL`/`PARSYA_POOL_API_TOKEN` в `.env`) и сам создаёт для него счётчик + цель `lead` + аккаунт Директа + кампанию. Токен не сохраняется в собственной SQLite этого приложения — читается на лету на каждый вызов.

Список доступных аккаунтов пула (для диагностики): `GET /api/parsya-pool/accounts`.

## Что уже подключено и что осталось

Уже реализовано:

- проверка токена Click.ru, список Direct-аккаунтов и интеграций (только просмотр);
- `POST /api/projects/{id}/campaigns/bulk-create` — массовый запуск: на каждый из `count` (1–20) провизионирует новый аккаунт из пула ParsYa, создаёт свой счётчик Метрики + цель `lead`, полный черновик кампании (объявление, ключевые фразы, случайный заголовок/текст/картинка из пулов проекта, сайтлинки, колл-ауты);
- каждая кампания создаётся ЧЕРНОВИКОМ (`Status=DRAFT`, `State=OFF`) — запуск показов не выполняется;
- базовая статистика Click.ru по расходам, кликам и показам.

Перед массовым запуском на реальном проекте проверьте один прогон с `count=1` и убедитесь, что счётчик/цель/кампания создались корректно.

Следующие этапы (см. `TASKS.md` в ParsYa):

1. ОРД/маркировка рекламы (ERID) — проверка `GET /markings/schemas/account` перед реальным запуском.
2. Явный, отдельно подтверждаемый переход кампании в активное состояние (запуск показов) — сознательно не реализован, требует прямого запроса.

Приложение не запускает кампании и не расходует рекламный бюджет автоматически.

## Секреты

Если токен ранее был отправлен в переписку или иначе мог стать доступным третьим лицам, перевыпустите его в Click.ru и используйте только новый токен в серверном `.env`.
