# Direct Campaign Manager

Веб-приложение для подготовки рекламных проектов Яндекс Директа через Click.ru API. Сейчас приложение позволяет сохранять проекты, проверять подключение Click.ru, создавать Direct-аккаунты и настраивать счётчик Метрики с JavaScript-целью `lead` через отдельный OAuth-токен Яндекса, заданный только на сервере. Создание рекламных кампаний, групп и объявлений ещё не подключено.

## Режим кампаний

В настройках проекта доступны два варианта:

- **Отдельные кампании** — одна кампания для Поиска и одна для РСЯ.
- **Одна ЕПК** — одна Единая перфоманс-кампания с включёнными местами показа Поиск и Рекламная сеть Яндекса.

Настройка сохраняется для каждого проекта. Это именно выбор шаблона создания, а не переключатель мест показа для уже существующих кампаний.

## Стек

- Python 3.12
- FastAPI + Uvicorn
- SQLite для начального развёртывания
- HTTPX для Click.ru API
- Защита интерфейса через HTTP Basic Auth

## Запуск локально или на сервере

```bash
python -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
cp .env.example .env
# Заполните .env уникальным паролем, CLICKRU_API_TOKEN и METRIKA_OAUTH_TOKEN
uvicorn --env-file .env app.main:app --host "${APP_HOST:-127.0.0.1}" --port "${APP_PORT:-8000}"
```

Откройте `http://127.0.0.1:8000`. Не публикуйте приложение в интернет без HTTPS и уникального пароля администратора. Для внешнего доступа используйте reverse proxy с TLS.

В Docker:

```bash
docker compose up --build -d
```

## Публикация через Nginx и HTTPS

Конфигурация поддомена `реклама.союзюристовроссии.рф` и пошаговые команды: [`deploy/README.md`](deploy/README.md). Сам сервер нужно настроить по SSH: репозиторий не имеет удалённого shell-доступа. Сначала запустите приложение на `127.0.0.1:8000`, затем включите Nginx reverse proxy и выпустите сертификат Certbot.

## Click.ru API

Базовый URL: `https://api.click.ru`. Документация и Swagger: https://api.click.ru/V0/docs/

Приложение использует:
- `GET /V0/user` — проверка токена;
- `GET /V0/integrations` — список подключённых интеграций;
- `GET /V0/accounts` — список рекламных аккаунтов;
- `POST /V0/accounts` — создание Direct-аккаунта с выбранной подключённой интеграцией Яндекс ID;
- `GET /V0/stat` — запрос статистики Click.ru (после выбора периода и аккаунтов).

Лимиты API и права доступа определяются Click.ru. Приложение не создаёт почтовые аккаунты Яндекса и не обходит этап подключения/авторизации Яндекс ID в Click.ru.

## Доступ к Яндекс Метрике

Для управления счётчиками требуется отдельный OAuth-токен Яндекса. Создайте приложение на странице [OAuth Яндекса](https://oauth.yandex.com/) для доступа к API и выдайте права `metrika:read` и `metrika:write`. Авторизуйте именно тот аккаунт, который имеет необходимые права на счётчики Метрики, и поместите выданный токен в `METRIKA_OAUTH_TOKEN` в серверном `.env`. Не добавляйте токен в Git или интерфейс. Для управления счётчиком через Management API токен должен иметь доступ к самому счётчику. См. [официальную документацию Яндекс Метрики по авторизации](https://yandex.com/dev/metrika/en/intro/authorization).

Один токен видит только те счётчики, к которым авторизованный аккаунт имеет доступ. Чтобы работать со счётчиками нескольких владельцев, предоставьте этому аккаунту нужные права в Метрике либо позже добавьте отдельное хранение OAuth-токенов для каждого пользователя.

## Что уже подключено и что осталось

Уже реализованы:

- проверка токена Click.ru, список Direct-аккаунтов и интеграций;
- создание Direct-аккаунта через `POST /accounts` с выбранным `integrationId`;
- прямое подключение к API Яндекс Метрики через `METRIKA_OAUTH_TOKEN` на сервере;
- поиск счётчика по домену проекта, создание счётчика при отсутствии, проверка существования цели и создание JavaScript-цели `lead`;
- сохранение ID счётчика и цели в проекте и вывод кода `ym(COUNTER_ID, 'reachGoal', 'lead');` для установки на сайт;
- базовая статистика Click.ru по расходам, кликам и показам.

Перед включением в рабочие процессы проверьте настройку Метрики на одном тестовом домене и подтвердите, что код счётчика установлен на сайте и событие отправляется только после успешной отправки заявки.

Следующие этапы:

1. Создание ЕПК или отдельных кампаний, групп, ключевых фраз, объявлений и изображений через Click.ru API-прокси Яндекс Директа.
2. Создание кампаний в остановленном состоянии с отдельным подтверждением перед запуском.
3. Отчёт по конверсиям `lead` через Reports API Директа и согласование НДС/атрибуции.
4. Массовое тиражирование на выбранные аккаунты, фоновые задачи, идемпотентность и журнал выполнения.

Приложение не запускает кампании и не расходует рекламный бюджет автоматически.

## Секреты

Если токен ранее был отправлен в переписку или иначе мог стать доступным третьим лицам, перевыпустите его в Click.ru и используйте только новый токен в серверном `.env`.
